Module 2 · SAE math — the gate, the shrinkage, the fix

The two diagrams below are the mental model for why JumpReLU exists.

A · The activation function (gate)

ReLU continuously ramps from 0 once π > 0.
JumpReLU stays at exactly 0 until π crosses a learned threshold θ, then jumps to the full pre-activation value.

B · The shrinkage problem (why JumpReLU helps)

Blue = the magnitudes a feature should have for perfect reconstruction. Orange = what ReLU+L1 actually outputs: every active feature is shrunk; weak ones die.
JumpReLU pays a flat L0 cost per active feature, so magnitudes stay correct once a feature is over threshold.

The decoder unit-norm constraint, geometrically

Every column of W_dec (i.e., every feature direction) lives on the unit sphere in ℝd_model. The optimizer is constrained to only rotate directions, never grow or shrink them. This closes the loophole where the SAE could scale W_dec[j] → k·W_dec[j] and z_j → z_j/k to satisfy L1 cheaply without changing reconstruction. After unit-norming, |z_j| measures the feature's true magnitude in input units — comparable across features.
